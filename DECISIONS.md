# Decision log

Short entries, newest last. Why we chose something, so future-me (and anyone reading the portfolio) can follow the thinking.

- **2026-10-01 · Prototype on the web first.** Validate the flow at the box before writing native code. A web page with real plate math was enough to learn what was missing.
- **2026-10-01 · Load rule: heaviest load inside the range.** For "75–78%" pick the heaviest load the plates can make inside the range; "80%+" picks the lightest load at or above 80%.
- **2026-10-02 · Only strength work matters.** The app reads the whole screenshot but keeps only blocks with % of 1RM. Learned at the box: a day can have two strength blocks.
- **2026-10-02 · Set number and reps are the headline.** At the box the set number was too faint; the load is secondary.
- **2026-10-02 · Built-in warm-up.** Three rounds up to the first working load, because working out the warm-up was the next piece of mental math at the box.
- **2026-10-03 · Scope: Train, PRs, Gyms, History.** Gym search via Google Places and shared gym setups are deferred (local-only v1).
- **2026-10-03 · Ask what was lifted only on the last set.** Keeps history honest and detects new PRs without adding friction to every set.
- **2026-10-04 · Anything with % is strength.** A block called "After Party" was missed. Also: when the % is hidden on the screenshot, ask instead of guessing.
- **2026-10-11 · Native Swift + RealityKit, not React Native or a web view.** Best feel and performance, and the point is learning native iOS. Cost: the 3D scene is rebuilt, not reused.
- **2026-10-11 · Build in 2D first, 3D after.** The math and flow must be right at the box before the 3D layer goes on top.
- **2026-10-11 · Free Apple developer account for now.** The app expires every 7 days; fine while building. Paid program when it's in weekly use.
- **2026-10-11 · Rules-first parsing, on device.** The box's format is regular; Vision OCR + rules works offline and free. AI only as a later fallback.
- **2026-10-13 · Any combination of plates counts as loadable.** The prototype only tried totals in jumps of 2 × the smallest plate, so with only 45/35/25/15/10 lb plates it skipped 115 lb (one 35 a side) for a 115.5 lb target and loaded 125. PlateKit follows SPEC 3.3: any sum of the gym's plates. Fixture updated.
- **2026-10-13 · A block can start with its label on the same line.** The box's app showed "C. After a Party" on one line, which wasn't read as block C. SPEC 3.6 rule 1 now accepts `C. After a Party`; the text after the dot is the label.
- **2026-10-14 · Sessions keep their lift names.** History should still say "Back Squat" after the workout it came from is deleted, so `Session` stores `liftNames` by block index.
- **2026-10-14 · History is a 4th tab.** Train · PRs · Gym · History; simplest in 2D, and the 3D wall calendar can link to it later.
- **2026-10-14 · "Type it in" is the simple form.** Lift, sets, reps, one %: fastest between sets. Per-set % still comes from screenshots.
- **2026-10-14 · M4 uses the spec look with the system font.** Black on white, square black buttons, outlined fields, orange background (SPEC 2.5) now, so screens aren't restyled later. Space Grotesk comes in when the font file is added.
- **2026-10-14 · Sessions keep each lift's PR unit.** Set totals are shown in the PR's unit (SPEC 3.2); storing `prUnits` with the session keeps that right even if a PR changes later.
- **2026-10-14 · Wrapped lines are joined before reading.** On 14/10 each Power Clean complex wrapped over 3 lines and block B was missed. SPEC 3.6 rule 2 now says how wrapped lines continue. Upload also takes several screenshots, in order, for workouts longer than one screen.
- **2026-10-14 · RPE blocks are read, with RPE × 10 suggested.** 14/10 block A was "@ 5/10 RPE". Instead of ignoring it, the app asks "What % for A?" with 50% filled in. Simple and predictable; an RPE chart was considered but has no values below RPE 6 and doesn't fit complexes. The PR is guessed from the first lift named and can be changed in Edit.
- **2026-10-14 · Screenshots are merged, not just joined.** 14/10 came as two overlapping screenshots, picked bottom first; E read "What's your ) PR?" from `(OR 60% 1RM)`. Blocks are now ordered by letter, overlap is dropped, and brackets/"or" are cleaned from names and PRs.
- **2026-10-14 · "2-3 Sets" means 2 rounds.** 14/10 E was a 10 + 5 deadlift pair for 2-3 sets; Will chose to repeat the pair twice. A range always means rounds; a plain "N Sets" with exactly N lines keeps each line as one set (a 5/3/1 wave stays 3 sets).
- **2026-10-14 · Sessions keep which PR each lift uses.** "Snatch Pull + Snatch" is checked against the Snatch PR; storing `prLifts` keeps that right even if the workout is edited or deleted. Also: "How much did you lift?" is asked after the last set of each lift and after any "+" set (SPEC 3.8).
- **2026-10-15 · 3D look: smooth shading + sketch outline (M5).** Tried in RealityKit on the phone: toon (3 flat shades) vs smooth lit shading, and no outline / clean line / sketch (two noise-jittered inverted hulls). Will picked **Smooth + Sketch**, line ~6 mm, roughness 0.3, and rounder shapes (plates 32 sides, bar 20) — "no need to be super low poly". The inverted hull needs no custom shader, so it's low risk for M6; its limit is silhouettes only. To fix in M6: RealityKit's tone mapping makes flat colours (the orange backdrop) darker than the palette.
- **2026-10-15 · Opening animation on every launch (for now).** Easier to test while M6 is built; revisit (first launch only?) before TestFlight.
- **2026-10-15 · Baked light instead of RealityKit lights (M6).** Next to the prototype, RealityKit's lit look was off: dark shadows, greyed whites from tone mapping, smooth borders. The prototype's light (sky 2.7 + sun from (−8, 20, 12), no tone mapping) is now baked in PlateKit (`Sunlight`): each face gets one of 4 flat shades, shadows are the props projected along the sun's rays onto the floor and walls, and the box's outer edges get a grainy double border. Everything is `UnlitMaterial`, so colours are exact. Limit: props don't shadow each other.
- **2026-10-15 · The 3D room is checked against the prototype itself.** Will had to point out differences one by one. Now the prototype's own code runs headless (Chromium + three.js) and PlateKit's bake is rendered next to it from the same camera shots; the room's recipes, light, shadows, ink lines and pictures were copied until the two match. This replaces the inverted-hull outline with the prototype's thin edge lines plus a rough border. Things fixed this way: a left-wall window strip and bench clutter the prototype hides, the missing cut-away of the wall facing the camera, plate numbers, the full wall fan, and shadows on the platform.
- **2026-10-16 · After the first real class: one session page, no check-offs.** Will used the app at the box. The session is now one scrolling page (kit on top, every set with its bar and changes, strip the bar, **End session**) with buttons to jump between kit and sets. Removed: Done per set, "How much did you lift?" and the new-PR check; history keeps the planned loads; duration runs from opening the session to End session. M4 is done.
- **2026-10-16 · Smaller kit, same plates per set.** Will asked for the fewest plates. Each set still uses its fewest plates per side; among equally short combinations the session picks the ones that share plates (01/10 lb squat kit 14 → 12, 05/10 14 → 12). Will chose this over carrying one more plate on the bar for an even smaller kit (14 → 10). Totals are unchanged; golden plate arrangements updated.
- **2026-10-16 · Playfair Display in the app.** Black weight, made from Google Fonts' variable font (SIL Open Font License, licence next to it in pl8/pl8/Fonts), for the flag.
- **2026-10-16 · Gym setup builds the room (M6 step 3).** First run shows the 3D room above the question sheet; each question flies to its station (name → flag, units and plates → shelf, bar → rack, PRs → PR board). The flag unrolls with the first letter, the shelf keeps a peg for every plate size of the unit (as in the prototype) and each pile pops on or off; the rack's bar gets shorter and thinner for lighter bars (prototype setBarModel). One `RoomStage` view serves first run and the 3D room screen.
- **2026-10-16 · Sheets fit their question; the room gets the rest.** Will found the first-run sheet took too much of the screen. Each question's sheet is now exactly as tall as its content (the PR list keeps half/full, as it can be long), and the room fills the screen above it.
- **2026-10-16 · The boards say what you entered (M6 step 4).** The PR board lists your PRs (lift left, PR right, as the prototype's drawPR) and updates live in first run; the whiteboard shows today's workout in Permanent Marker ("Today's sesh", each lift's sets and first working load, as drawWB). Permanent Marker (Apache 2.0) is added to the app next to Playfair.
- **2026-10-16 · Name step types onto the flag.** With the keyboard up there was no room to see the flag, so the name step has no visible field: you type, the name appears on the flag, return or Continue moves on.
- **2026-10-16 · PR screenshots from the box app.** Its list puts the weight beside the lift, read as separate lines; weight-only lines now pair with waiting lift names (SPEC 3.7). Fixture `Fixtures/prs/2026-10-16-app`.
- **2026-10-16 · One PR per lift; replay starts clean.** Will got "backsquat" next to "Back Squat". Lift names now match whatever the spacing or case (SPEC 3.7), imports update the existing PR, and duplicates already saved are merged on launch (newest value kept, history moved). "Replay the first run" asks, then erases gym, PRs, workouts and history. The name step's hidden field now owns its focus and asks for the keyboard after the sheet is up; tapping the hint brings it back.
- **2026-10-16 · PR lists: rows rebuilt, pairs in either order.** On the phone only Back Squat came through: Vision sorted a row's weight and name by height with a tiny tolerance, so a weight could come before its lift. PR screenshots now join side-by-side pieces into one line per row, the parser pairs a name and a weight in either order and ignores the row arrow, and the import shows the text it read so a bad read can become a fixture.
